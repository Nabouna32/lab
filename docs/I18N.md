# Loculary — Internationalization

French and English are the initial languages. The architecture must scale to many languages without a hard-coded maximum.

Global UI strings belong in locale files. Tool-specific names, descriptions and metadata are separate structured content. Larger editorial/documentation content can use structured Markdown/MDX or an equivalent content layer. User-facing strings must not be hard-coded in tool logic.

Use a language registry with enabled state, locale metadata, text direction and translation status. `translationStatus` is a product readiness signal, not an automatic structural check: `complete` means the locale's currently supported user-facing translation scope has been reviewed and declared complete; `partial` means the locale is usable but that review has not established completeness or at least one translation domain is intentionally incomplete. Matching keys or content structure alone never changes the status. Partial translations may be published with a clear indicator. English is the product fallback language when a translation is missing; French is the other initial supported language. Anticipate RTL now. Localized SEO requires deliberate URL and metadata design.


## Public URL localization

English is the reference and default locale for the initial launch, with French as the second complete launch locale. Public tool URLs are fully localized for the selected language: English uses `/en/tools/<category>/<tool>`, while French uses `/fr/outils/<categorie>/<outil>`.

Internal identifiers remain English and language-neutral. Category and tool route slugs are localized routing data. Language switching must resolve the same resource in the target locale, and canonical URLs, hreflang alternates, internal links and sitemaps must use the localized route.

## Initial locale detection

When a public URL has no explicit locale prefix, the edge proxy negotiates the initial locale from the browser's `Accept-Language` header. French preferences select `/fr`, English preferences select `/en`, and unsupported languages fall back to the default English locale. Explicit `/fr` and `/en` URLs are never overridden by browser language preferences.
